# Журнал работы с AI

Дата работы: 20 октября 2026 года. Инструмент: Codex. AI использован для разбора требований, проектирования, написания интерфейса, серверной части, тестов и документации.

Это сохранённый технический журнал фактической работы, а не полный дословный экспорт диалога. Исходная переписка с запросом и результатами инструментов сохраняется в Codex для возможного обсуждения на интервью. В журнал не включены учётные данные, системные инструкции и приватные пути окружения.

## 1. Запрос и требования

Пользователь попросил полностью выполнить тестовое задание FutureToday, учесть требования, перепроверить решение и подготовить формат сдачи. Предоставлены ссылка на DOCX и скриншот кабинета с лимитом одного файла/архива до 2 МБ.

Из DOCX извлечены требования: сервис форм для менеджера и студента; публикация по ссылке; просмотр ответов; обязательное использование AI; публичный GitHub; Node.js ≥20; запуск `npm install`, `npm start`; localhost:3000, PORT; автономность; данные внутри проекта; `/admin` без авторизации; сохранение лога AI.

## 2. Принятые решения

- Сначала обеспечить ключевой сценарий из четырёх шагов.
- Использовать встроенные модули Node.js и браузерный JavaScript без npm-зависимостей, сборки и внешних сервисов.
- Хранить данные в JSON с последовательной атомарной записью и защитой от второго процесса.
- Добавить только связанную с исходной проблемой аналитику прохождения вопросов.
- Разделить черновик и публикацию; сохранять снимки вопросов для исторических ответов.
- Сделать публичную форму пошаговой, с прогрессом, возвратом и проверкой ответов.
- Подготовить README, обоснование решений, отчёт проверки и файл со ссылкой для кабинета.

## 3. Реализация

AI создал четыре серверных модуля, интерфейс конструктора, публичную форму, просмотр ответов, CSV и статистику. Добавлены ограничения запросов, проверка Host/Origin, заголовки CSP, экранирование HTML, защита CSV от формул. Случайные UUID используются для форм и посещений. До отправки значения ответов на сервер не передаются.

При собственной проверке AI исправил обработку `null`/массивов вместо JSON-объекта, обработку нестандартных идентификаторов полей, блокировку редактирования во время сохранения и склонение количества вопросов. Код отформатирован инструментом Prettier, который не стал зависимостью проекта.

## 4. Проверки и исправления

- Первые 13 автоматических проверок прошли на Node.js 26 и отдельно на Node.js 20.20.2.
- Через браузер создана новая форма, добавлен список вариантов, выполнена публикация и отправка. Ошибка обязательного поля, сохранённые ответы и статистика проверены визуально.
- Добавлены две проверки настоящего запуска: пользовательский PORT/перезапуск процесса и ошибка неверного PORT.
- Проверка подмены Host сначала падала: `fetch` в Node.js 20 не передавал подменённый Host. Тест переведён на `node:http`, после чего он проверяет реальный HTTP-запрос. Серверная проверка Host оставлена.
- Итог: 15/15 тестов на Node.js 20.20.2 и 15/15 на Node.js 26.10.0; синтаксические проверки пройдены.
- Тестовые данные не публикуются. Полный список проверок и ограничения — в `docs/TEST_REPORT.md`.

## 5. Что стоит уметь объяснить на интервью

Почему JSON достаточен для этого MVP; как очередь и атомарная запись предотвращают потерю обновлений; чем отличаются ревизия черновика и опубликованная версия; как повторная отправка остаётся безопасной; почему метрика остановок не доказывает причину ухода; какие изменения нужны перед реальным размещением и обработкой данных.

AI-лог намеренно оставлен в репозитории, согласно заданию. Он не заменяет понимание решения автором сдачи.
