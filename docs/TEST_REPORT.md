# Отчёт проверки

Дата: 20 октября 2026 года. Среда локальной проверки: macOS, Node.js 20.20.2 и 26.10.0.

## Автоматические проверки

- `npm install` — успешно, внешних зависимостей нет.
- `npm run check` — синтаксическая проверка серверных и клиентских модулей пройдена.
- `node --test` на **Node.js 20.20.2** — **15/15**, ошибок и пропусков нет.
- `npm test` на **Node.js 26.10.0** — **15/15**, ошибок и пропусков нет.

| Область | Проверенный результат |
| --- | --- |
| Основной сценарий | Создание → сохранение → публикация → посещение → отправка → просмотр → CSV |
| Валидация | Обязательность, email, список, отметка, типы/длины, лишние вопросы, некорректные схемы |
| Черновики/версии | Сохранение не меняет публикацию; новая версия отделена от старой; активное посещение может отправить старый снимок |
| Конфликты | Устаревшая ревизия получает 409 |
| Состояния | Черновик недоступен публично; закрытая форма возвращает 410; повторное открытие работает |
| Параллельность | 12 одновременных регистраций одного посещения дают один sessionId; 20 одновременных отправок дают ровно один отклик |
| Повторная отправка | Возвращается прежний ID, новый ответ не создаётся |
| Защита запросов | Некорректный JSON, неверный тип тела, cross-site Origin, Host, размер запроса, неизвестный sessionId, неподдерживаемый HTTP-метод |
| CSV | Unicode, разделители, кавычки, переносы, нейтрализация формулы |
| Аналитика | Метрики и остановки по версиям; до отправки не сохраняются значения ответов или IP |
| Ограничения | 181-й публичный POST за минуту получает 429 и Retry-After |
| Хранилище | 25 конкурентных записей без потерь, откат ошибочной мутации, защита вторым процессом, сохранность после открытия заново |
| Повреждение данных | Некорректный файл вызывает ошибку и остаётся без изменений |
| Запуск | Реальный дочерний процесс с пользовательским PORT; HTTP доступен; после SIGTERM и перезапуска ID формы сохраняется |
| Ошибки настройки | Некорректный PORT завершает процесс с понятной ошибкой |

## Браузерный сценарий

В браузере проверены:

1. Создание формы «Проверка полного сценария».
2. Ввод описания и добавление третьего вопроса.
3. Переключение вопроса на список и ввод трёх вариантов.
4. Публикация; появление публичной ссылки.
5. Открытие ссылки в отдельной вкладке, начало заполнения.
6. Попытка продолжить без имени — видимая ошибка у поля, фокус остаётся на вопросе.
7. Ввод тестового имени и email `student@example.com`, выбор «Разработка», отправка.
8. Успешное подтверждение; в админке один отклик с правильными ответами.
9. Статистика: 1 посещение, 1 начало, 1 отправка, конверсия 100%, незавершённых шагов нет.
10. Визуальная проверка списка форм и статистики при ширине окна 730 px: текст и основные действия доступны, таблица статистики помещается.

Тестовые персональные сведения вымышлены и не входят в поставляемый файл данных. Рабочая база исключена из репозитория. При первом запуске у проверяющего будет чистая демонстрационная форма без ответов.

## Пределы проверки

Это проверка локального MVP, а не нагрузочный аудит или полная проверка доступности. Отдельные реальные мобильные устройства и все сочетания браузеров/скринридеров не проверялись. В CI настроена дополнительная матрица Node.js 20, 22, 24 на Ubuntu; результаты доступны на вкладке Actions репозитория.
