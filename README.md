# FutureToday Forms

Автономный сервис форм отклика на стажировки и карьерные события. Менеджер создаёт и публикует форму, студент заполняет её по ссылке, менеджер видит ответы и воронку заполнения.

## Запуск

Нужен **Node.js 20 или новее** с npm. Из корня репозитория выполните ровно две команды:

```sh
npm install
npm start
```

Откройте **http://localhost:3000/admin**. Корневой адрес http://localhost:3000 также показывает список форм.

Сборка, `.env`, API-ключи, Docker и установка СУБД не нужны. Сторонних npm-зависимостей нет; сервер, тесты и интерфейс используют стандартные возможности Node.js и браузера. Внешние шрифты, CDN, облачные API и трекеры не подключаются. Интернет для работы сервиса не нужен.

При первом старте автоматически появляется **одна демонстрационная опубликованная форма без откликов**. Можно сразу открыть её или создать свою.

## Проверка за 3 минуты

1. В `/admin` нажмите **Создать форму**, укажите название.
2. В конструкторе измените описание, добавьте вопрос, выберите тип и обязательность. Для списка укажите варианты с новой строки. Стрелки меняют порядок вопросов.
3. Нажмите **Опубликовать**. Форма сначала сохраняется, затем публикуется. **Сохранить** обновляет только черновик.
4. Нажмите **Открыть форму** или **Скопировать ссылку**. Ссылка имеет вид `/f/<uuid>` и остаётся прежней при обновлении публикации.
5. Как студент нажмите **Начать заполнение**, ответьте на вопросы и отправьте отклик. Обязательные вопросы и email проверяются в браузере и на сервере.
6. В админке откройте вкладку **Отклики**. Разверните отклик; при необходимости скачайте CSV. Кнопка **Обновить** загружает новые данные.
7. Во вкладке **Статистика** видны открытия, начала заполнения, отправки и остановки по вопросам. Для проверки остановки откройте форму в отдельной вкладке, начните заполнение и оставьте её незавершённой.
8. Перезапустите сервис: формы, ссылки, отклики и статистика сохранятся. Закрытие и повторное открытие приёма доступны внизу конструктора.

## Что реализовано

- Конструктор: название, описание, от 1 до 20 вопросов, изменение порядка и удаление вопроса из черновика.
- Пять типов: короткий текст, email, длинный текст, список, отметка. Вопросы могут быть обязательными.
- Черновик и опубликованная версия разделены. Редактирование черновика не меняет форму для студента до публикации.
- Уникальная постоянная ссылка, закрытие и повторное открытие приёма.
- Пошаговое заполнение, прогресс, возврат к предыдущему ответу, ошибки рядом с вопросом, подтверждение успешной отправки.
- Ответы хранят снимок вопросов соответствующей версии. Уже открытая вкладка может отправить старую версию после публикации новой; закрытие приёма блокирует и такие отправки.
- Повтор отправки в рамках одного посещения возвращает тот же отклик, без дубля. Конкурентные записи сериализуются.
- Просмотр ответов и CSV с UTF-8 BOM, разделителем `;`, экранированием кавычек/переносов и нейтрализацией формул.
- Воронка по версиям. Предпросмотр в конструкторе не создаёт посещение.
- Адаптивная вёрстка, подписи полей, клавиатурный фокус, уведомления об ошибках, отсутствие внешних ресурсов.

## Настройки

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `PORT` | `3000` | Целое число 1–65535 |
| `DATA_FILE` | `data/store.json` | Путь к файлу данных; относительный путь считается от корня проекта |

macOS/Linux:

```sh
PORT=3100 npm start
```

Windows PowerShell:

```powershell
$env:PORT=3100; npm start
```

По умолчанию сервис слушает только `127.0.0.1`. Разрешены Host `localhost`, `127.0.0.1`, `[::1]`; соединение доступно по IPv4. Это локальный MVP, как требуется в задании. Админка и её API **без авторизации по условию**. Не выставляйте этот экземпляр с реальными ответами в публичный интернет.

## Данные и надёжность

Все данные находятся в `data/store.json`, который создаётся автоматически и исключён из Git. Для резервной копии остановите сервер и скопируйте этот файл. Для чистого запуска остановите сервер и перенесите файл в резервную папку. Следующий запуск создаст новую демонстрационную форму. Не редактируйте файл при работающем сервисе.

Запись выполняется через временный файл, `fsync` и атомарное переименование. Неудачная операция не меняет текущий снимок в памяти. Повреждённый существующий JSON не перезаписывается: сервер останавливается с ошибкой. Lock-файл исключает одновременную работу двух процессов с одним хранилищем; после обычного завершения он удаляется, после аварии проверяется PID владельца. Если lock-файл пуст/повреждён, нужно убедиться, что процесс остановлен, и удалить его вручную.

Лимиты MVP: 100 форм, 20 вопросов на форму, 50 000 посещений всего, тело запроса до 128 КиБ; публичные POST-запросы ограничены 180 запросами в минуту на IP. IP используется только для временного счётчика в памяти и не записывается в файл. Передача ответов до отправки отсутствует: события аналитики содержат только идентификаторы шагов.

## Как читать аналитику

Посещение определяется случайным идентификатором в `sessionStorage`: одна вкладка + одна версия формы. Обновление страницы обычно не создаёт нового посещения; новая вкладка, очищенное хранилище или новая версия могут создать новое. Это не число уникальных людей. Если `sessionStorage` недоступен, идентификатор живёт до обновления страницы.

- **Открыли** — успешно загрузили публичную форму и зарегистрировали посещение.
- **Начали** — нажали «Начать заполнение» или перешли к вопросу.
- **Дошли** — открыли этот шаг или более поздний.
- **Прошли** — перешли дальше; необязательный вопрос можно пропустить.
- **Остановились** — не отправили отклик, а этот вопрос остался самым дальним открытым шагом.
- **Конверсия** — отправленные отклики / посещения × 100%, округление до целого.

«Остановились» включает активных студентов, которые ещё заполняют форму. Мы не утверждаем, что они окончательно ушли, и не делаем вывод о причине. Сетевые ошибки аналитики также могут влиять на показатели. События можно подделать через API: это диагностический сигнал, а не антифрод-система. Данные каждой версии показываются отдельно, чтобы изменение вопросов не искажало сравнение.

Ответы до отправки находятся только в памяти вкладки. Возврат между шагами сохраняет их; обновление или закрытие страницы — нет. После успешной отправки значения очищаются из памяти. Автосохранение персональных данных в браузере намеренно не добавлено.

## Проверки

```sh
npm run check
npm test
```

15 автоматических проверок: валидация типов и границ, основной сценарий, версии, конфликты редактирования, закрытие/открытие, параллельные отправки, обработка ошибочных запросов, ограничения, CSV, сохранность хранилища, реальный перезапуск процесса и настройка `PORT`. Тесты создают временные файлы и не меняют рабочие данные.

GitHub Actions запускает проверки на Node.js 20, 22 и 24. Фактические результаты ручной и автоматической проверки: [docs/TEST_REPORT.md](docs/TEST_REPORT.md).

## Устройство проекта

```text
src/server.js       Запуск, PORT, завершение процесса
src/app.js          HTTP-маршруты, API, заголовки и ограничения
src/domain.js       Схемы, проверка ответов, версии, аналитика, CSV
src/store.js        Файловое хранилище, очередь и атомарная запись
public/             Интерфейс без сборки и внешних ресурсов
test/               Тесты node:test
data/               Локальные данные, не попадают в Git
docs/               Обоснование решения и отчёт проверки
AI_LOG.md           Журнал использования AI
```

Решения по объёму MVP, ограничения и следующие шаги: [docs/DESIGN.md](docs/DESIGN.md). AI использован при проектировании, написании кода, тестов и документации; журнал сохранён в [AI_LOG.md](AI_LOG.md). Эта переписка в Codex также сохраняется для обсуждения на интервью.
